# Карта заведений: с сайтом и без

Интерактивная самообновляемая карта заведений (кафе, магазины, салоны, мастерские, клиники, офисы…).
Каждое заведение помечено цветом:

| Цвет | Что значит |
|---|---|
| 🔴 **Нет сайта** | в OpenStreetMap не указан ни сайт, ни соцсети — главные кандидаты на разработку сайта |
| 🟠 **Только соцсети** | есть лишь страница во «ВКонтакте», Telegram, на агрегаторе и т. п. |
| 🟣 **Сайт не открывается** | сайт указан, но при автоматической проверке домен не существует или страница отдаёт 404 |
| 🟢 **Есть сайт** | собственный сайт указан |

Сайт полностью статический: сервер и база данных не нужны, достаточно GitHub Pages.

## Возможности

- Карта с кластерами: кольцо кластера показывает доли статусов внутри него.
- Фильтры: статус сайта, категория, «только с телефоном», «скрыть сетевые», «только в видимой области», поиск по названию/адресу/телефону.
- Список отсортирован по «перспективности»: сначала без сайта и с телефоном.
- **Мини-CRM**: для каждого заведения — статус лида (В планах → Связался → Переговоры → Делаю сайт → Сайт сделан / Отказ) и заметка. Хранится в браузере (localStorage), переносится кнопками «⬇ Лиды» / «⬆ Лиды».
- Экспорт отфильтрованного списка в CSV (открывается в Excel).
- Кнопка «Скопировать предложение» — готовый вежливый текст обращения к владельцу.
- Быстрые ссылки для ручной проверки: Яндекс Карты, 2ГИС, поиск сайта, объект в OSM.
- Поиск города/адреса и кнопка **«Загрузить эту область»** — живые данные OpenStreetMap для любого места, не дожидаясь автообновления.
- Ссылкой с положением карты можно поделиться (`#масштаб/широта/долгота`), светлая и тёмная темы, работает на телефоне.

## Как устроено самообновление

`.github/workflows/update.yml` раз в сутки (и при каждом пуше, и вручную — кнопка *Run workflow*):

1. запускает тесты;
2. `scripts/update-data.mjs` запрашивает Overpass API по областям из `config.json`, проверяет доступность сайтов и пишет `data/places.json`;
3. если данные изменились — коммитит их в репозиторий;
4. публикует сайт на GitHub Pages.

Если Overpass недоступен или вернул подозрительно мало данных, прежние данные не перезаписываются.

### Что нужно включить один раз

1. **Settings → Pages → Build and deployment → Source: GitHub Actions.**
2. Обновление и публикация выполняются только из **ветки по умолчанию** репозитория (расписание GitHub Actions работает только в ней).

До первого успешного обновления в `data/places.json` лежат демонстрационные (вымышленные) данные — сайт прямо об этом предупреждает.

## Настройка города

`config.json`:

```json
{
  "areas": [
    { "name": "Москва — центр", "bbox": [55.73, 37.58, 55.78, 37.66] }
  ],
  "checkSites": true
}
```

`bbox` — прямоугольник `[юг, запад, север, восток]` в градусах. Областей может быть несколько.
Удобно подобрать на <https://boundingbox.klokantech.com> (формат CSV даёт порядок «запад, юг, восток, север» — переставьте).
Большие области автоматически делятся на несколько запросов.

## Локальный запуск

```bash
npm run serve      # сайт на http://localhost:8080
npm run update     # обновить data/places.json (нужен доступ в интернет, Node 20+)
npm test           # тесты
```

Зависимостей для установки нет: Leaflet и Leaflet.markercluster лежат в `vendor/`.

## Структура

```
index.html, css/style.css   интерфейс
js/app.js                   логика карты, фильтров, карточки
js/osm.js                   запрос Overpass и разбор тегов (общий для сайта и скрипта)
js/categories.js            справочник категорий OSM → русские названия и значки
js/leads.js                 мини-CRM, CSV, текст предложения
scripts/update-data.mjs     автообновление данных
config.json                 области и настройки
data/places.json            данные (обновляются автоматически)
tests/                      тесты (node --test)
```

## Важно знать о точности

- Источник — OpenStreetMap. «Нет сайта» означает «сайт не указан в OSM»: у части заведений сайт на самом деле есть, просто его никто не внёс. Перед обращением проверьте через «Искать сайт» / Яндекс Карты / 2ГИС.
- Проверка «сайт не открывается» намеренно осторожная (только несуществующий домен или 404/410), чтобы не было ложных срабатываний из-за защиты от ботов и географических ограничений. Она выполняется с серверов GitHub, поэтому результат всё равно стоит перепроверить.
